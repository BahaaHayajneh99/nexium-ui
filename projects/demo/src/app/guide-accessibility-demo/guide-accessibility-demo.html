Accessibility

{{ commonService.appName }} components are built on native HTML elements wherever possible (native <input>, <button>, <label>) so they inherit the browser's built-in accessibility behaviour for free.

Form Controls

Inputs, checkboxes, radios, selects and the autocomplete all bind aria-invalid when their invalid input is set, and forward disabled to the underlying native control so assistive technology reports the correct state.

Keyboard & Focus

Interactive elements use :focus-visible outlines instead of suppressing focus styles, and components that project custom content (modal, dialog, popover) keep focusable elements in the natural tab order rather than trapping or hiding them.

Labels

Always pass a label input (or project one) for form controls - it's rendered as a real <label> associated with the control, not just placeholder text.
