Migration Guide

This guide will help you upgrade to the latest version of {{ commonService.appName }} or migrate from other component libraries.

Upgrading {{ commonService.appName }} Versions

Before upgrading, always review the release notes for breaking changes and deprecations.

Step 1: Backup Your Project

Create a git commit or backup before upgrading:

git commit -m "Before {{ commonService.appName }} upgrade"

Step 2: Update Package

Update {{ commonService.appName }} to the latest version:

npm update nexium-ui

Step 3: Update Dependencies

Update Angular and other peer dependencies:

ng update @angular/core @angular/common

Step 4: Review Breaking Changes

Check the release notes for any breaking changes specific to the components you use

Step 5: Test Your Application

Thoroughly test your application to ensure all components work correctly:

npm test && npm run serve

Migration from Other Libraries

From Angular Material

Angular Material import { MatButtonModule } from '@angular/material/button';
→
{{ commonService.appName }} import { NxButtonComponent } from 'nexium-ui';

Main difference: {{ commonService.appName }} has zero external dependencies and works as standalone components

From ng-bootstrap

If you're migrating from ng-bootstrap to {{ commonService.appName }}:

  • Replace NgbModule imports with component imports
  • Update template bindings to use component properties
  • Use {{ commonService.appName }}'s theme system instead of Bootstrap SCSS
  • Run your test suite to verify compatibility

From PrimeNG

When migrating from PrimeNG to {{ commonService.appName }}:

  • Replace PrimeNG component imports with {{ commonService.appName }} equivalents
  • {{ commonService.appName }} uses simpler APIs with fewer configuration options
  • Theme system is simpler - just CSS custom properties instead of multiple theme files
  • No need for PrimeFlex - use built-in layout components or your CSS framework

Breaking Changes by Version

Check the appropriate section below for the version you're upgrading to:

v2.0.0 (Current)

  • Angular 21+ required
  • All components are standalone (no NgModule version available)
  • Signal-based inputs available as alternative to @Input

v1.x to v2.0 Migration

  • NgModule imports are no longer supported
  • Update all component imports to standalone versions
  • Some component APIs have been simplified
